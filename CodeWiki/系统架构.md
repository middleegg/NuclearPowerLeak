# 系统架构

## 1. 架构总览

NuclearPowerLeak 采用典型的 **Mindustry Java Mod 分层架构**，以**内容注册驱动**为核心模式。整体架构可分为四层：

```
┌───────────────────────────────────────────────────────┐
│                  核心入口层 (Entry Layer)              │
│  nu.java (Mod Lifecycle) · NuUI.java (HUD 挂载)        │
├───────────────────────────────────────────────────────┤
│                  内容定义层 (Content Layer)            │
│  NuItems · NuLiquid · NuBlocks · Azer                  │
│  ModStats · Recipe · ConsumeRecipe                     │
├───────────────────────────────────────────────────────┤
│                  扩展机制层 (Extension Layer)          │
│  NewItemsType (属性扩展) · ConfigurableBlock (机制扩展)│
├───────────────────────────────────────────────────────┤
│              Mindustry API & Arc 框架 (基础层)         │
│  mindustry.mod.Mod · mindustry.type.* · arc.*          │
└───────────────────────────────────────────────────────┘
```

### 1.1 架构设计原则

| 原则 | 体现 |
|------|------|
| **注册驱动** | 所有内容通过静态 `load()` 方法在 `loadContent()` 阶段注册 |
| **链式配置** | 采用双花括号初始化块 `{{ ... }}` 简化配置代码 |
| **扩展优先于修改** | 通过继承 `Item`/`Block` 等类扩展功能，不修改原版 |
| **分层解耦** | 内容定义与机制实现分离，便于单独维护 |

## 2. 模块职责划分

### 2.1 包结构与职责矩阵

| 包路径 | 职责 | 关键类 | 依赖方向 |
|--------|------|--------|----------|
| `Npl` | 入口与 UI | `nu`, `NuUI` | → 依赖 content 和 newSth |
| `Npl.content` | 游戏内容注册（数据层） | `NuItems`, `NuLiquid`, `NuBlocks`, `Azer`, `ModStats`, `Recipe`, `ConsumeRecipe` | → 依赖 newSth + Mindustry API |
| `Npl.newSth` | 机制扩展与类型系统（机制层） | `NewItemsType`, `ConfigurableBlock` | → 仅依赖 Mindustry API + ModStats（单向） |

## 3. 核心加载流程（生命周期）

Mindustry Mod 的生命周期由游戏引擎驱动，NuclearPowerLeak 的加载时序如下：

```
游戏启动
    │
    ▼
Mod 实例化 (nu() 构造函数)
    │
    ├───► 注册 ClientLoadEvent 监听器
    │
    ▼
loadContent() 被引擎调用
    │
    ├───► NuItems.load()      注册 16 种自定义物品
    ├───► NuLiquid.load()     注册 4 种自定义液体
    ├───► Azer.load()         注册 Azer 星球及规则
    └───► NuBlocks.load()     注册自定义方块（含配方）
    │
    ▼
ClientLoadEvent 触发
    │
    └───► 延迟 10 tick 显示 "frog" 欢迎对话框
    │
    ▼
玩家进入 Azer 星球
    │
    ├───► 应用 Azer.ruleSetter 中的游戏规则
    ├───► 加载初始物资 (100 生铁)
    └───► RTS AI 启动

游戏中玩家建造方块
    │
    └───► ConfigurableBlock 处理配方切换 / 生产
```

### 4.3 配方数据模型

`Recipe` 类采用统一的数据结构表示任意生产配方：

| 字段 | 类型 | 说明 |
|------|------|------|
| `inputItems` | `Seq<ItemStack>` | 物品输入 |
| `outputItems` | `Seq<ItemStack>` | 物品输出 |
| `inputLiquid` | `Seq<LiquidStack>` | 液体输入 |
| `outputLiquid` | `Seq<LiquidStack>` | 液体输出 |
| `inputPayload` | `Seq<PayloadStack>` | Payload 输入 |
| `outputPayload` | `Seq<PayloadStack>` | Payload 输出 |
| `craftTime` | `float` | 制作时间（tick） |
| `priority` | `int` | 优先级（多配方排序用） |

## 5. UI 架构

### 5.1 自定义 UI 挂载策略

`NuUI.init()` 采用**降级挂载策略**，确保兼容性：

```
尝试在 HUD 的 overlaymarker > bottom 位置挂载
    │
    ├── 成功 ──► bottom.add(panel).right().bottom().pad(10)
    │
    └── 失败 ──► 创建全屏 Table，设置 fillParent
                     └── bottom().right() 定位后手动 addChild
```

### 5.2 方块配置 UI

`ConfigurableBlock.buildConfiguration()` 复用原版 `ItemSelection.buildTable()` 组件：
- 支持多行多列选择网格（默认 2 行 × 4 列）
- 显示所有已解锁、未禁用的输出物品
- 点击切换当前配方

## 6. 持久化与版本兼容

`ConfigurableBlock.UnitFactoryBuild` 实现了自定义序列化：

| 字段 | 序列化方式 |
|------|-----------|
| `progress` | `write.f()` / `read.f()` |
| `currentPlan` | `write.s()` / `read.s()` |
| 版本号 | `version() = 3`，支持旧版本兼容跳过 |
